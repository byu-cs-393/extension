# Meeting Summary — 2026-05-11

Planning conversation between the CS 393 instructor and Jack (RA) scoping a Chrome extension project for the class. Full transcript in [notes-5-11-2026.md](notes-5-11-2026.md).

## Summary

The instructor's overarching goal: keep students consistent throughout the semester, catch them when they fall behind, and improve assessment integrity — without losing the "human touch" of TA help.

### Key themes

- **Topic exam workflow.** TAs should be able to sign off topic exams from the extension (with a code or PIN). The extension should auto-report grades to **Canvas** (Learning Suite is being dropped) using the instructor's Canvas API key, fronted by a backend service so the key isn't exposed.
- **Detecting falling-behind students.** Surface alerts to TAs/instructor when a student goes silent for a week or two, or when their pace drops below a threshold — so outreach can happen *before* they spiral.
- **Detecting copy-paste / AI use.** Three signals discussed:
  1. Copy-paste detection in the editor.
  2. Keystroke recording so a TA (or the student themselves) can replay how a solution was typed.
  3. Linearity check (deferred — recording covers it).

  Privacy rule: whatever you store, the student must be able to see it. BYU previously approved this kind of tracking but requires a clear privacy statement.
- **Motivation / gamification.** Inspired by Duolingo — anonymous head-to-head matchups against 10 random classmates of similar level, weekly leaderboards, opt-in competition. Make showing percentile mandatory (not optional) — students benefit from knowing where they stand.
- **Restructuring topic exams.** Split into two kinds: **performance exams** (problems announced in advance — student practices, then performs in 15 min) and **articulation exams** (novel problems, student talks through their thinking). Different role for the TA in each.
- **Collaboration features.** "6 other students are working on this problem right now — click to start a Teams chat." Possibly track mock-interview pairings via unique per-student passwords.
- **Final project (longer-term).** Instructor's stretch idea: replace LeetCode with their own site where the final project is students contributing problems + test cases. Browser-side execution (WASM/JS) to avoid server compute costs. For *this* semester, focus on the extension only; the site is an "if we have time" stretch.
- **Tech stack.** Chrome extension (frontend) + Firebase (Firestore for per-user/per-class JSON docs) + Google Cloud Functions (Lambda-equivalent) for backend. Auth via LeetCode cookie + BYU netID + name/student-ID confirmation on first connect. Use `chrome.storage.sync` (~1 MB) for cross-device key sync, `chrome.storage.local` (~20 MB) for bulk.
- **Distribution.** Publish via the instructor's Chrome Web Store developer license; GitHub auto-deploy on manifest version bump.
- **Schedule.** Instructor is traveling for ~3 weeks (1 week UK + 2 weeks elsewhere) — skip meetings during that window; Jack works asynchronously. Pick back up after.
